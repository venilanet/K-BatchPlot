# K-BatchPlot 交付前自查清单（强制）

用户 2026-11-19 立的要求：修改 K-BatchPlot 不能只满足功能需求，助手必须承担完整的开发自检责任。
**不要等用户安装后发现问题再报，必须在交付之前主动检查、主动发现、主动修复。**
用户负责最后的真实环境验收，助手负责在交付之前尽可能消灭所有能够提前发现的问题。
不要让用户充当测试人员和错误报告工具。

## 一、安装与卸载专项检查（最高优先级）

从普通用户的实际使用角度检查整个安装链路：

- 安装包、BAT、PowerShell 脚本是否完整。
- 安装脚本是否使用正确的项目根目录。
- DLL、依赖文件、bundle 文件是否全部复制到正确位置。
- 是否正确识别 AutoCAD 2014，而不是默认选择其他版本。
- 是否正确处理 AutoCAD 不同安装路径。
- 是否正确处理 Windows 7 的 PowerShell 版本兼容性。
- 是否正确处理中文用户名和包含空格的路径。
- 是否正确创建或修改注册表加载项。
- 是否正确配置 AutoCAD 信任路径。
- 是否存在重复注册、重复加载的问题。
- 是否存在旧版本残留导致新版本加载失败。
- 是否可能出现安装成功但 CAD 实际没有加载插件的情况。
- 安装失败时是否能够明确提示失败原因。
- 重复安装是否安全。
- 覆盖升级是否安全。
- 一键卸载是否彻底。
- 卸载后图框库、用户配置是否按设计保留。
- 卸载后重启 CAD 是否还会自动加载插件。

特别检查之前出现过的注册表加载问题。不能只删除一个注册表键就认为卸载完成，
必须检查所有实际加载入口，包括 AutoCAD 启动套件、ApplicationPlugins Bundle、
注册表按需加载、受信任路径等。不得随意删除其他插件的注册表配置或用户数据。

## 二、完整安装生命周期测试

不要只检查安装脚本语法。必须模拟以下场景：

1. 全新安装。2. 已安装旧版本后覆盖升级。3. 同一版本重复安装。4. 安装中途失败。
5. 安装目录已存在。6. 安装路径包含中文。7. 用户名包含中文。
8. AutoCAD 2014 安装在非默认目录。9. 机器同时安装多个 AutoCAD 版本。
10. 卸载后重新安装。11. 卸载后重启 CAD。12. 安装后第一次启动 CAD。
13. 安装后关闭 CAD 再次启动。14. 插件 DLL 被占用时执行升级或卸载。

没有真实 CAD 环境时，至少使用模拟注册表、模拟目录和脚本测试覆盖可验证的部分，
并明确剩余限制。

## 三、代码修改后的全项目回归检查

每次修改一个功能，都必须检查它是否破坏其他功能。重点：

插件能否正常加载；菜单和命令是否正常；图框扫描、图框属性读取、图框库、纸张匹配、
批量导出、导出前检查、预览、失败重试、PDF 合并是否正常；临时文件是否正确清理；
取消操作是否安全；CAD 系统变量是否正确恢复；清单编辑是否正常；
用户手动修改的数据是否会被覆盖。

特别注意：新功能不能只测试自己，还要测试与原有功能的组合。

## 四、点选图框功能专项自查

是否真的支持连续点选多个块；Enter 是否正常结束；Esc 是否正常取消；
非块对象是否正确跳过；重复块是否去重；再次点选是否只追加新对象；
原有清单是否保持不变；用户手动修改的图号和图名是否保留；
块属性 TAG 是否读取正确；无属性块是否仍然进入清单；
旋转、缩放、非等比缩放后的边界是否正确；
动态块拉伸、可见性切换是否存在边界问题；
失败对象是否能明确标记，而不是生成错误 PDF。

不要因为静态代码检查通过，就声称动态块边界已经验证。

## 五、兼容性检查

目标环境：Windows 7 64 位 / AutoCAD 2014 / .NET Framework 4.0。逐项检查：

- 项目 TargetFramework 是否正确。
- 编译工具链是否符合目标环境。
- 是否引用了 AutoCAD 2014 不存在的 API。
- 是否使用了高版本 .NET 才支持的方法。
- 是否引入了不兼容的第三方 DLL。
- DLL 平台目标是否正确。
- x86 / x64 配置是否合理。
- 安装脚本是否使用了 Win7 不支持的 PowerShell 语法。
- 中文路径、文件编码和注册表路径是否正常。

不要为了开发方便偷偷升级框架或改变目标平台。

## 六、主动发现问题，而不是只按清单打勾

每次交付前，主动问自己：

1. 用户第一次安装，最可能在哪一步失败？
2. 用户升级旧版本，最可能残留什么？
3. 用户重复执行操作，是否会产生重复数据或重复注册？
4. CAD 意外关闭，会留下什么状态？
5. 某个图框异常，会不会影响其他图框？
6. 文件被占用、路径不存在、权限不足时会发生什么？
7. 是否存在静默失败？
8. 是否有错误被 catch 后只记录日志，却没有通知用户？
9. 是否有功能看起来成功，实际没有完成？
10. 是否有只在开发环境正常、在 Win7 上失败的代码？

不仅检查用户提出的要求，还要主动寻找用户没有想到的问题。

发现问题后：能修复的直接修复；修复后重新执行相关测试；检查修复是否引入其他问题；
无法修复的明确说明原因和影响；不得隐瞒问题，不得用 PASS 掩盖未测试项目。

## 七、交付前必须执行的检查

每次准备推送 GitHub 前，必须完成：

1. 检查所有修改文件。2. 检查是否有遗漏的项目编译项。3. 检查安装和卸载脚本。
4. 检查注册表操作。5. 检查 AutoCAD API 兼容性。6. 执行全部可运行的自测。
7. 执行静态检查。8. 执行安装脚本模拟测试。9. 执行卸载脚本模拟测试。
10. 检查 Git diff，确认没有意外修改。11. 检查 GitHub 推送结果和最新 commit。
12. 确认本地与远端代码一致。

## 八、最终交付报告

每次交付必须提供：本次新增功能；修改文件列表；主动发现的问题；已修复的问题；
安装测试结果；卸载测试结果；静态检查结果；自动化测试结果；
AutoCAD API 兼容性检查结果；尚未验证的项目；最新 GitHub commit。

测试状态必须严格区分：

- A. 已通过实际测试。
- B. 已通过自动化测试。
- C. 已通过静态代码检查。
- D. 仅完成代码修改，尚未测试。
- E. 因环境限制无法验证。

绝对不允许把 D 或 E 写成 A。
